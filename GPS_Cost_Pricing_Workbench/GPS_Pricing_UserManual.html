Getting Started
Opening the Workbench
No installation, no Python, no server. Just open a file in Chrome or Edge.
1
Open the Launcher
Double-click GPS_Cost_Pricing_Workbench.html in Chrome or Edge. This is your home screen for all stages.
2
Select a Stage
Click any active stage card (3–6) to open it directly. Each stage runs as a standalone HTML file in the same folder.
3
Enter Your Name
Each stage asks for your name on first launch. This is saved locally for audit trail purposes.
4
Create a Pricing Cycle
All work is organized by cycles (e.g., "FY26 Q1"). Create a new cycle from the dashboard before importing data.
Browser Requirements
Use Chrome or Edge (Chromium-based).
Firefox may have IndexedDB restrictions for local files.

Address bar should start with file:///C:/... — not a network path like \\server\share.
Data Storage
All data is stored in your browser's IndexedDB — completely local, no cloud, no network.

Each stage has its own isolated database. Clearing browser data will erase all cycles.
Offline Setup (one-time)
On first use on a machine without internet, run setup_offline.bat inside each stage folder to download JS libraries locally.
Stage 3
Sales Cost
Calculator
Transforms Projected Service Cost (PSC) into Sales Cost by applying dimension-driven uplift rules across service tiers, geographies, and delivery types.
Stage 3 · Sales Cost Calculator
How It Works
Sales Cost = PSC × (1 + Total Uplift Ratio)
Where Total Uplift Ratio = sum of all active uplift factors assigned to the matched catalog rule
3-Layer Configuration System
  • Layer 1 — Uplift Factors: 18 pre-seeded dimension types (COUNTRY, SRVTIER, SDTYPE, etc.). Each factor has a name and optionally a ratio value.
  • Layer 2 — Uplift Catalogs: Define the scope — Type of Service + GEO — and which factors apply within that scope.
  • Layer 3 — Uplift Rules: Released rules assign concrete match values and ratios per factor. A SKU matches a rule when all its dimensions align.
Key Dimensions
  • Product Tiers: ThinkPad, IdeaPad, Legion, Commercial
  • Service Types: 1yr Base, 3yr Base, 5yr Base, 3yr ADP, Premier 3yr
  • Geographies: NA, EMEA, APJ, China
  • Delivery: Onsite, Depot, Remote, etc.
SKU Import
  • Excel (3-sheet reference format) or CSV paste
  • Download template from the SKU Data tab
  • Edge cases handled: No Rule match, No PSC value

Rule Matching Logic
A SKU matches a rule when all factor match values align with the SKU's dimensions. The first matching released rule wins. Unmatched SKUs are flagged as No Rule.
Export Format
The export produces a multi-sheet Excel compatible with Stage 4's import format. Columns include Part#, Tier, Upgrade, Delivery Type, and Sales Cost per geo region.
Stage 4
GVE Validation
Engine
A 4-layer validation engine that checks the structural integrity of the Sales Cost matrix — before it is used to derive list prices.
Stage 4 · GVE Validation Engine
4 Validation Layers
All layers run against Sales Cost. Layers 1–3 always run; Layer 4 requires a prior baseline.
Layer 1
Monotonicity
Average sales cost must be non-decreasing across tiers when sorted by tier sequence. Grouped by Region × Delivery Type × Upgrade Years.
Critical
Layer 2
Ratio Bands
Year-over-year cost ratios (3yr/1yr, 5yr/3yr, 4yr/2yr) must fall within configured floor/ceiling bands. Grouped by Tier × Delivery Type × Region.
Critical Warning
Layer 3
Cross-Geo Deviation
Per-region average cost vs. cross-region mean. Flag if deviation exceeds threshold (default 20%). 3+ regions breaching = Systemic.
Warning Systemic
Layer 4
YoY Drift
Year-over-year change against a prior cycle baseline. Cell-level (per SKU+region) and geo-level (regional average) checks. Requires baseline CSV.
Critical Warning
Default Thresholds
Ratio bands: 3yr/1yr 1.8–2.8 · 5yr/3yr 1.3–1.7 · 4yr/2yr 1.3–2.0
Cross-geo deviation: 20% · YoY cell drift: 25% · YoY geo avg: 20%
Violation Resolution
Each violation can be resolved with an explanation. Resolved violations are tracked in the Audit Log. Cycles with unresolved Critical violations cannot be submitted.

Cycle Lifecycle
  • Draft: Active working state. Import, run GVE, resolve violations.
  • Submitted: Locked read-only state. All Critical violations must be resolved before submission. Export GVE report from this state.
Settings

  • Overhead: Total fixed cost ÷ projected units
  • Ratio Bands, Drift Thresholds: Configurable per cycle
  • Tier Sequence: Define sort order for monotonicity checks
Stage 5
List Price
Calculator
Derives Channel Price and List Price from Sales Cost and PFV (market benchmark), applying add-on adders, TopSeller discount, and geo-group pricing logic.
Stage 5 · List Price Calculator
How It Works
Stage 5 combines Sales Cost with PFV (Price Forward Validation) market benchmark data to compute final commercial prices.
Model A · C→L
Channel Price First
C-Price = Adj_PFV × (1 − ratio)
List Price = C-Price ÷ (1 − ratio)
Start from PFV-adjusted channel price, then derive list price using the C→L ratio. Used when channel price is the market anchor.
Model B · L→C
List Price First
List Price = Adj_PFV × TopSeller_factor
C-Price = List Price × (1 − ratio)
Start from PFV-adjusted list price (with TopSeller discount), then derive channel price. Used when list price is the market anchor.
No PFV
Cost-Based Fallback
C-Price = Sales Cost ÷ (1 − GP%)
List Price = C-Price ÷ (1 − ratio)
When no PFV benchmark is available, prices are derived directly from Sales Cost using configured GP% margin.
PFV — Price Forward Validation
An external market benchmark matrix (imported as Excel). PFV values anchor the pricing calculation. Adj_PFV = PFV × (1 + adjustment%) applies configurable adjustments before use.
Add-Ons & TopSeller
SKUs with add-on flags (ADP, KYD, SBTY, TI CRU, Premier) receive adder values on top of base price. TopSeller SKUs receive a discount factor applied to the list price.

PFV Status Flags
  • PFV Applied: Benchmark data found and used
  • No PFV: No benchmark — cost-based fallback applied
  • PFV Adjusted: Benchmark used with manual adjustment
GP% Check
  • GP% = (C-Price − Sales Cost) / C-Price
  • Displayed per SKU for margin health review
  • Negative GP% indicates C-Price is below Sales Cost — flagged for review
Stage 6
Price Gradient
Validation
Validates the structural integrity of final list prices — the same 3-layer logic as Stage 4, but applied to commercial prices rather than costs.
Stage 6 · Price Gradient Validation
3 Validation Layers
All layers run against List Price (list_price_calc) from Stage 5. Can also validate externally-sourced price data.
Layer 1
Price Monotonicity
Average list price must be non-decreasing across tiers when sorted by tier sequence. Grouped by Region × Delivery Type × Upgrade Years. Mirrors Stage 4 L1 but on prices.
Critical
Layer 2
Price Ratio Bands
List price ratios (3yr/1yr, 5yr/3yr, 4yr/2yr) must fall within configured floor/ceiling bands. Ensures proportional pricing across service terms. Same thresholds as Stage 4.
Critical Warning
Layer 3
Cross-Geo Deviation
Per-region average list price vs. cross-region mean. Flag if deviation exceeds threshold (default 20%). 3+ regions breaching elevates to Systemic. Mirrors Stage 4 L3 on prices.
Warning Systemic
Stage 4 vs Stage 6 — Design Intent
  • Stage 4 validates cost structure integrity (Sales Cost matrix)
  • Stage 6 validates price gradient integrity (List Price matrix)
  • Both use the same 3-layer logic; Stage 4 adds Layer 4 (YoY Drift)
  • Stage 6 operates closer to commercial reality — the final price seen by customers
Data Sources
  • Stage 5 cycles: Reads list_price_calc directly from Stage 5 IndexedDB
  • Manual import: CSV or Excel with columns: part_number, tier, upgrade_years, region, list_price_calc
  • No prior baseline required — Layer 4 (YoY) is not in scope for Stage 6
Reference
Violation Severity Levels
Used in Stage 4 (GVE) and Stage 6 (Price Gradient) validation results.
Severity Applies To Meaning Cycle Impact
Critical L1 Monotonicity
L2 Ratio (below floor)
L4 Cell Drift		 A structural rule is definitively broken. The pricing matrix is not commercially acceptable in its current form. Blocks submission. All Critical violations must be resolved before a cycle can be submitted.
Systemic L3 Cross-Geo
