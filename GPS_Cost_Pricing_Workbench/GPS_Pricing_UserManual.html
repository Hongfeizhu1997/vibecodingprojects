1. Tool Overview

The GPS Cost Pricing Workbench is a browser-based offline pricing tool for Lenovo's GPS service pricing team. It guides you through a 6-stage pipeline from raw cost data to validated list prices, with a built-in pricing history database and dashboard.

Key Features

• No installation — opens directly in Chrome or Edge

• All data stored in a local SQLite database with automatic CSV backup

• Each stage is a self-contained page with cross-stage navigation

• Full audit trail: every pricing change is recorded (who, what, when, old→new)

• Streaming import handles large files (tested up to 200K rows)

• CSV bidirectional sync: export for Excel analysis, import to update the database

2. Getting Started

1 Start the Server

cd GPS_Cost_Pricing_Workbench
python3 server.py 8080

Then open http://localhost:8080/GPS_Cost_Pricing_Workbench.html in your browser.

⚠ Important: Use python3 server.py, NOT python3 -m http.server. The custom server handles SQLite data persistence and CSV import/export. The standard server will silently fail to save your data and show blank pages.

2 The Launcher

The launcher page shows all 6 stages as cards with descriptions. Stages 1 and 2 are marked Coming Soon. Click any active stage (3, 4, 5, or 6) to open it. The Dashboard card opens your pricing history.

3 Navigation

Every stage page has a top navigation bar with links to all other stages. Jump between stages without going back to the launcher.

4. Stage 3 — Sales Cost Calculation

Stage 3

Calculates Sales Cost from Standard Cost (PSC) by applying dimension-driven uplift rules.

Formula

Sales Cost = PSC × (1 + Σ Uplift %) + Σ Uplift $

4.1 Import SKU Data

Go to Import tab → click Choose File. Required columns: Service PN, Standard Cost (Base Cost), Country, Service Tier, GEO. Supported formats: CSV and Excel (.xlsx).

For large files (50K+ rows), the tool automatically switches to streaming import with a progress bar.

4.2 Uplift Rules

Go to Uplift tab → Uplift Values → Import your CSV. Each rule matches SKUs by dimensions (GEO, tier, country, etc.) and applies a percentage uplift. Only Released status rules are active.

4.3 AIPC Attribute

Click the green/gray AIPC badge in the data grid to toggle Yes/No per PN. AIPC is available as an uplift factor — create rules like "AIPC=Yes → +10%".

4.4 Send to Stage 4

Calculate tab → Run Calculation → Export tab → Send to Stage 4. Stage 4 opens automatically with data pre-loaded.

5. Stage 4 — GVE Validation

Stage 4

Validates the Sales Cost matrix against 4 pricing integrity layers.

5.1 GVE Layers

LayerRuleExample
L1Monotonicity1YR < 3YR < 5YR for same tier
L2Ratio Bands3YR ÷ 1YR must be 1.8–2.8
L3Cross-Geo DeviationSame tier/term across countries: max dev < 20%
L4YoY DriftYear-over-year change < 25%

5.2 CrossCheck Engine

Additional rule-based validation for priority hierarchy, term ordering, and GEO-specific constraints. Create custom rules via the Rule Designer in the CrossCheck tab.

5.3 Export & Acknowledge

Export GVE and CrossCheck results to Excel. Use Batch Acknowledge to group violations by root cause and acknowledge all at once.

6. Stage 5 — List Price Derivation

Stage 5

Derives Channel Price and List Price from Sales Cost using PFV (Price Floor Value) benchmarks.

6.1 Formula

PFV = Base PFV + ADP + KYD + SBTY + TICRU + Priority

Adj PFV = PFV × Regional Factor

List Price / Channel Price = Adj PFV × TopSeller × (1 ± Ratio)

GP% = (Channel Price − Sales Cost) ÷ Channel Price

6.2 PFV Import

Go to PFV tab → import your PFV benchmark CSV. Format:

tier,term_years,delivery_type,geo,base,adp,kyd,sbty,ticru,priority
TP Premium,3,Onsite,DE,318,50,30,20,15,10

6.3 Pricing Models

ModelDirectionWhen to Use
C→LCost → ListStart from Sales Cost, derive List Price
L→CList → CostStart from target List Price, back-calculate

6.4 GP Floor Rules (Multi-Dimensional)

Configure minimum GP% thresholds by Country, SLA Type, and Term. Matching priority:

Exact (Country + SLA + Term) → Country + SLA → Country only → Global default (30%)

Go to Settings → GP Floor Rules → Add Rule. Rules with higher specificity automatically override generic ones.

6.5 Send to Stage 6

Calculate → review results → Send to Stage 6.

7. Stage 6 — Price Gradient Validation

Stage 6

Validates final List Prices across 3 structural layers to ensure pricing integrity.

7.1 Validation Layers

LayerRuleWhat It Checks
L1MonotonicityHigher tier → higher price
L2Ratio BandsPrice ratios between tiers/terms are reasonable
L3Cross-GeoSame product across countries has consistent pricing
Note: Stage 6 uses the same GVE engine as Stage 4, but L4 (YoY Drift) is disabled — standalone list price validation only needs structural layers.

7.2 Results

Each PN gets a PASS / WARN / FAIL status with detailed violation info showing which layer failed, the expected range, and the actual value. Export results to Excel.

8. Dashboard — Pricing History

Dashboard

Your personal pricing database. View all cycles, track PN pricing over time, and manage data import/export.

8.1 Main View

The dashboard landing page shows:

Stats cards: Total Cycles, Unique PNs, Total Records, Latest Activity

Cycle table: All pricing cycles with PN count, average GP%, last updated

8.2 View a Cycle

Click any cycle name → see all PNs with Sales Cost, List Price, Channel Price, GP%, GVE/Gradient status. Use the search box to filter by PN.

8.3 PN History & Trends

Click Trend on any PN → three panels open:

  1. Pricing History table — all cycles this PN appeared in, with prices and GP% per cycle
  2. GP% Trend — shows ▲+Xpp or ▼-Xpp between oldest and newest cycle
  3. Change Log — field-level audit: every value change, old→new, timestamp

8.4 CSV Import/Export

ButtonWhat It Does
⬇ Export CSVDownloads the complete pricing database as a CSV file. Open in Excel for analysis, share with colleagues, or archive.
📤 Import CSVUpload a CSV file to upsert records. New records are added; existing records are updated with changes logged.
CSV is bidirectional: Export → edit in Excel → Import back. The database is the master; CSV is the exchange format.

9. Data Persistence & Backup

Where is my data?

All pricing data is stored in pricing_master.db (SQLite database) in the project folder. This is the primary store. CSV is for import/export only.

Backup Strategy

Daily: Export CSV from Dashboard → save to a network drive or cloud folder.

Before major changes: Export CSV as a named snapshot.

Automatic: Every field change is logged in the audit trail (Change Log panel).

Restore from CSV

Dashboard → Import CSV → select your backup. Records are upserted — existing data is updated, new data is added, nothing is deleted.

10. Best Practices

🏷 Cycle Naming: Use FY26_Q3_EMEA format. Makes Dashboard filtering and PN history tracking more useful.

📊 GP Floor: Start with a global 30% threshold. Add country/SLA-specific rules as you identify regional differences.

📦 Large Data: 10K rows = instant. 50K+ = streaming with progress bar. Up to 200K supported.

🔗 Bridge: Always use "Send to Stage N+1" buttons. They auto-transfer and pre-load the next stage.

📝 Audit: Use the Change Log in Dashboard to review who changed what and understand pricing decisions over time.
