## 一句话定位

**IDG E-com B2C 服务定价从"按 Tier 固定价格"升级为"按 HW AUR Band × 期限意愿曲线 × 服务 Tier Factor"的算法模型。**

---

## 核心公式

```
ServicePrice = Base3YBandPrice × TermFactor × TierFactor
```

| 变量 | 含义 | 来源 |
|------|------|------|
| **Base3YBandPrice** | 3 年期 PS 基准价，按 HW AUR Band 查表 | 每季度按 AUR 分布自动重算 |
| **TermFactor** | 期限折价因子，反映客户"额外年份感知价值递减" | 对数曲线：`0.55 × ln(Term) + 0.65` |
| **TierFactor** | 服务等级倍数 | Depot 0.55 / Onsite 0.75 / PS 1.00 / PSP 1.40 |

### 成本修正（α 和 γ）

针对 4-5 年长期限，引入两个成本修正因子，防止定价低于真实成本：

```
FinalTermFactor = (0.55 × ln(Term) + 0.65) × (1 + α × max(0, Term−3)) × (1 + γ × max(0, Term−3))
```

| 参数 | 含义 | 生效条件 |
|------|------|---------|
| **α** | 稳态成本上升（人工+零件通胀） | Term > 3 |
| **γ** | 尾部风险（故障率+零件稀缺） | Term > 3 |

| Tier (SMB) | α | γ | 理由 |
|------------|:--:|:--:|------|
| Depot | 0 | 0 | 无年龄敏感 |
| Onsite | 0.02 | 0 | |
| PS | 0.03-0.04 | 0.03-0.05 | 可预测支持成本 |
| PSP | 0.07-0.09 | 0.08-0.10 | ADP + 密封电池尾部风险 |

## 期限因子（Term Factor）

基于行为经济学：客户对额外年份的感知价值呈对数递减。

```
TermFactor = 0.55 × ln(Term) + 0.65
```

| Term | Base (log) | Depot | Onsite | PS | PSP |
|:----:|:----------:|:-----:|:------:|:--:|:---:|
| 1Y | 0.65 | 0.65 | 0.65 | 0.65 | 0.65 |
| 2Y | 1.03 | 1.03 | 1.03 | 1.03 | 1.03 |
| 3Y | 1.25 | 1.25 | 1.25 | 1.25 | 1.25 |
| 4Y | 1.41 | 1.41 | 1.44 | 1.53 | 1.69 |
| 5Y | 1.54 | 1.54 | 1.60 | 1.80 | 2.18 |

> 4-5 年期 PSP 的 TermFactor 显著高于 Depot——反映长尾风险成本。

## 自动校准机制

每季度自动执行：

1. 拉取最新 HW AUR 分布（按子系列）
2. 重新分桶到 Band A-J
3. 按 Band 中位数更新 3Y 锚值
4. 应用对数期限曲线重新生成所有 SKU 价格

### 风控（Guardrail）

| 指标 | 下限 | 上限 |
|------|:---:|:---:|
| PS 1Y | 8% of HW AUR | — |
| PSP 5Y | — | 22% of HW AUR |

### AI 调优（可选）

- 如果某 Band 的 Attach Rate 环比下降 >2pt → 降低该 Band 的服务系数 5%
- 如果某 Band 的 Attach Rate 飙升 → 适度上调价格

## 问题与架构对比

### 当前痛点

| 问题 | 证据 |
|------|------|
| 服务价格与 HW 价值无关 | HW AUR vs Service AUR 线性相关 r ≈ 0.08（接近随机） |
| 同 Tier 内价格一刀切 | $1,200 和 $2,000 的 Carbon 同价 |
| List Price 天花板滞后 | List Price 更新跟不上 HW 价格变化 |
| 低端过度收费，高端收费不足 | Entry 端保护/设备比过高，Halo 端过低 |

### Dell 对标

Dell Pro Max 14，3 种配置：HW 涨 41% → 服务涨 92%。Dell 3Y PS 约为 HW 价格的 14-15%。

### 与 ISG Dynamic Pricing 的差异

| 维度 | ISG B2B（已有） | IDG E-com B2C（新） |
|------|------|------|
| **公式** | ServicePrice = HWPrice × PenRate | ServicePrice = BaseBandPrice × TermFactor × TierFactor |
| **定价粒度** | PenRate 查表 | HW AUR Band（10-12档）+ 期限曲线 |
| **期限影响** | 固定倍率 | 对数递减曲线 + α/γ 成本修正 |
| **行为模型** | 无 | 客户感知价值递减（行为经济学） |
| **校准频率** | — | 季度自动重算 Band + 锚值 |
| **AI 调优** | — | 基于 Attach Rate 闭环反馈 |
| **实施系统** | LBPi/LBPe（B2B 渠道） | REDPORT → HLS-POS + APOS（电商） |
| **决策速度** | 天级（商机/合同） | 实时（电商页面） |

## 与 SSG Enablement Agent 的关系

IDG E-com B2C 定位为 Dynamic Pricing 的**独立子方案**，与 ISG B2B 并行：

- **共同底层**：都遵循"服务价格应随硬件价值变化"的核心原则
- **不同实现**：ISG 走 PenRate 查表 + 逐步 AI 化；IDG E-com 走算法模型（对数曲线 + Banding）
- **与 SEA 的接口**：IDG E-com 的 Base Band Price 锚值需要 CPM/SCFE 的成本数据作为输入校验（不依赖 List Price）
