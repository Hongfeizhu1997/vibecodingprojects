# SSG Dynamic Pricing — 产品价格推荐方案 V2

> 2026-07-06 | Dynamic Pricing 子项目
> 面向业务决策层 | 侧重：方案逻辑 · 业务效果 · 落地路径

---

## 1. 一句话定位

**做 Dynamic Pricing——让服务的价格跟着硬件的价格走。**

在 B2B 商机→报价→合同→订单的销售流程中，当销售配置完硬件 + 服务后，系统自动推荐每项服务 PN 的 Sales Price。推荐价随 HW 价格联动：HW 涨价服务价跟涨，HW 降价则自动上调服务渗透率（Pen Rate），确保服务收入不因 HW 打折而被等比拖低。

---

## 2. 为什么现在必须做

### 2.1 现状：同一服务 Tier 下，不同 HW 的价格差异被忽略

当前服务定价以 Service Tier 为主要维度：3 年 Premier Support 对所有 HW 型号收取相同的 Pen Rate（如均为 HW 渠道价的 8%）。但同一个 Tier 下，不同 HW 的价格和价值差距可能极大：

| 对比 | ThinkPad X1 Carbon | ThinkBook 14 | 差异 |
|------|---------------------|--------------------|------|
| HW 渠道价 | $2,000 | $800 | **2.5×** |
| 3yr Premier Support（Pen Rate 8%） | $160 | $64 | **2.5×** |
| 实际服务交付成本差异 | ~1.5× | — | 远小于价格差 |
| **结果** | Margins 可能偏低（服务定价未反映高 HW 价值） | Margins 偏高但竞争力弱（客户愿付的服务费有限） | **两个方向都在漏利润** |

**问题本质**：同一个 Service Tier 用一个 Pen Rate 覆盖所有 HW，忽略了 HW 之间的价值和成本差异——高价值 HW 上服务定价不足（margin leakage），低价值 HW 上可能竞争力不足。

### 2.2 目标：让服务价格反映 HW 的价值差异

| 场景 | 当前（同一 Pen Rate） | 方案实施后（动态 Pen Rate） |
|------|---------------------|--------------------------|
| 高价值 HW | 服务价被 Pen Rate 锁死，无法充分捕获 HW 价值 | Pen Rate 适度上调，服务价格反映实际 HW 价值 |
| 低价值 HW | 服务价绝对值低，但 Pen Rate 一刀切，竞争力不足 | Pen Rate 灵活调整，在 $/HW 目标内找最优平衡 |
| HW 降价 10% | 服务收入等比缩水 | 引擎自动上调 Pen Rate，服务收入不被等比拖低 |
| 新客群冷启动 | 按全局平均 Pen Rate | 模型借用相似客群经验，推荐精度高于全局均值 |

## 3. 方案：怎么做到服务价格跟 HW 走

### 3.1 核心逻辑

当前的问题本质是「一个服务 Tier 一个 Pen Rate」。方案的核心思路：**把 Pen Rate 从一个固定值变成一个由多维度决定的动态值。**

```
HW Channel Price ──┐
服务 Tier × Term   ──┼──→ 推荐引擎 ──→ 动态 Pen Rate ──→ Service Sales Price
GEO × 客户段       ──┤                    │
HW 价值段          ──┘              随 HW 价格波动自动调整
```

**用具体例子说明**：以 3 年 Premier Support 为例。

| | ThinkPad X1 Carbon | ThinkBook 14 |
|---|---|---|
| HW 渠道价 | $2,000 | $800 |
| 当前 Pen Rate | 8%（一刀切） | 8%（一刀切） |
| 当前服务价 | $160 | $64 |
| **方案后 Pen Rate** | **10%** | **7%** |
| **方案后服务价** | **$200** | **$56** |
| 效果 | 服务定价充分反映 HW 高端定位 | 降低客户总拥有成本感知，提升竞争力 |

高价值 HW 的 Pen Rate 上调（因为服务交付成本更高、客户价值感知更强），低价值 HW 的 Pen Rate 反而可以下调（降低门槛、提升 attach 率）。**两个方向都在优化利润结构。**

### 3.2 引擎如何决定 Pen Rate

推荐引擎基于四个维度查找或计算最优 Pen Rate：

| 维度 | 说明 | 举例 |
|------|------|------|
| **HW 价值段** | HW 渠道价分档（$0-500 / $500-1000 / $1000-2000 / $2000+） | X1 Carbon 落在 $1500-2000 段 |
| **服务 Tier × Term** | 服务等级 + 合同年限 | Premier Support × 3 年 |
| **GEO × 客户分层** | 区域市场 + 客户级别 | EMEA × Enterprise |
| **竞争信号**（Phase 2+） | 竞品服务定价、历史成交/丢单数据 | 同区域同类客户段的赢单价格区间 |

引擎根据这四个维度，在历史交易数据中学习每个组合的最优 Pen Rate，输出推荐值。同时叠加三道约束校验：

1. **不亏**：Service Sales Price ≥ Service Cost
2. **合理**：Service Sales Price ≤ List Price（不超过官方标价）
3. **可控**：Pen Rate 偏离历史均值超过阈值时，自动标记为「低置信度」，推人工审批

### 3.3 在 B2B 销售流程中的落点

```
商机(Opportunity) → 报价(Quote) → 合同(Contract) → 订单(Order)
                         ↑
                    Dynamic Pricing 推荐触发点
                    输入：HW 配置 + 服务选择 + 客户/GEO
                    输出：每项服务 PN 的推荐 Sales Price
```

销售在报价工具中配置完硬件和服务后，系统自动计算推荐价并填入报价单。销售可以直接采纳，也可以修改——但超阈值修改需填写原因。整个过程对销售不增加额外步骤。

### 3.4 三个设计原则

| 原则 | 说明 |
|------|------|
| **学习而非预设** | Pen Rate 不从人工规则表查，从历史交易数据中学——系统自动发现「$2,000 的 X1 Carbon，3 年 Premier Support 最合理的 Pen Rate 是 10% 而不是 8%」 |
| **独立于 HW 定价** | Dynamic Pricing 引擎不与 PAIDS（HW 定价系统）耦合。PAIDS 输出的 HW 价格只是引擎的输入特征之一——引擎独立决策服务价格，不被 HW 定价策略绑定 |
| **渐进信任** | POC 阶段离线验证 → Pilot 阶段推荐仅供参考 → Rollout 后自动填入但保留人工覆盖 → Wave 2 高置信推荐自动通过。信任是逐步建立的，每一步都可回退 |

## 4. 技术路线（三个方向，聚焦业务效果）

以下三个方向不是互斥的——建议 Wave 1 用方向 B 快速启动，Wave 2 切换方向 A，Wave 3 引入方向 C。

### 方向 A：精准型（贝叶斯分层模型）

**做什么**：按 GEO / 客群 / 服务 Tier 分层建模，学习每层内「价格→成交」的关系，每笔推荐附带置信度。

**业务效果**：
- 小市场不翻车：LA 数据少时自动借用 EMEA 经验，不会给出离谱价格
- 每笔推荐带置信度：低于置信阈值的推荐自动推人工审批——「这笔我不太确定，你看一下」
- 可解释："这个报价比基准高 5%，因为该客户段历史数据显示对价格不敏感"

### 方向 B：速赢型（XGBoost + 优化层）

**做什么**：用历史交易特征训练模型，直接输出推荐 Pen Rate，叠加业务约束（≥成本、≤List Price、$/HW 达标）。

**业务效果**：
- 2-3 周可出第一版推荐表，供 POC 阶段人工比对验证
- 自动捕捉非线性关系：HW 价格 × 服务 Tier × Term 的交叉效应无需人工预设规则
- 团队已有 XGBoost 经验（GPS/SSR 项目），学习成本低

### 方向 C：进阶型（价格弹性模型）

**做什么**：直接估计「降 X% 价→成交概率升 Y%」的因果效应，可在推荐的同时做「如果全线调价会怎样」的模拟推演。

**业务效果**：
- 直接回答定价决策的核心问题：「这个客户段的价格弹性是 -0.3」
- 模拟推演："如果 Q3 HW 预计降 8%，提前把服务 Pen Rate 调到 X%，预计 $/HW 影响为 Y"
- 定价决策从「事后看报表」升级为「事前做推演」

### 路线选择建议

```
POC (方向 B) → Pilot (方向 B) → Rollout (方向 B) → Wave 2 (方向 A 替换) → Wave 3 (方向 C 叠加)
   2 个月           3 个月            1 个月            +6 个月               +12 个月
```

## 5. 业务效果量化

### 5.1 直接收益

| 指标 | 当前 | 目标 | 验证方式 |
|------|------|------|---------|
| 新 GEO 冷启动推荐精度 | 全局均值（一刀切） | 优于全局均值 30%+ | 留一法交叉验证 |
| 销售采纳率 | — | Pilot 期 ≥ 60% | 报价工具埋点统计 |
| $/HW 波动率 | 随 HW 价格等比波动 | 波动幅度缩小 50%+ | 季度对比 |

### 5.2 三个典型场景

**场景 1：HW 大单降价，服务利润不崩**

某大客户 EMEA 区，ThinkPad 企业采购大单 HW 折扣 15%。当前：所有服务 PN 的 Sales Price 被等比压低 15%（因为 Pen Rate 固定）。方案后：系统识别该客户段 $/HW 目标，自动上调服务 Pen Rate 5-8pp，守住服务收入底线。

**场景 2：HW 涨价，释放 space 抢 attach**

某产品线 HW 供不应求、渠道价上涨 8%。当前：服务价跟涨 8%（客户在 HW 上已经多付了，服务再加价容易引发抵触）。方案后：Pen Rate 适度下调 2-3pp，服务价格仅涨 5%，降低客户总拥有成本感知，提升服务 attach 率。

**场景 3：新 GEO 冷启动，不拍脑袋**

AP 新市场数据积累不足，当前只能按全局 Pen Rate 报价。方案后：模型自动收缩到相似 GEO（EMEA）的先验经验，推荐精度高于全局一刀切。

## 6. 落地节奏

### Wave 1：6 个月（当前项目范围）

| | POC | Pilot | Rollout |
|---|---|---|---|
| **时间** | 2 个月 | 3 个月 | 1 个月 |
| **范围** | 1 个 GEO（EMEA）+ 3 个服务 Tier | 全部 GEO + 全部 Tier | 嵌入报价流程 |
| **技术交付** | 离线跑通模型（方向 B），产出推荐 Pen Rate 表，与历史人工报价逐笔对比 | 模型接入报价工具，销售在报价界面看到「AI 推荐价」字段 | 推荐价自动填入报价单，销售确认或修改即可 |
| **业务流程** | 不改变销售流程 | 试点销售团队新增推荐价字段，追踪采纳率 | 推荐价自动填充，超阈值修改需记录原因 |
| **业务 KPI** | 输出「AI vs 人工」偏差分析报告 | AI 采纳率（目标 ≥ 60%） | AI 采纳率 + 价格偏离度纳入日常 KPI |
| **团队准备** | 无需培训 | 1 次 15 分钟销售培训 | IT 嵌入报价工具（开发+UAT） |
| **风险** | 🟢 零风险：离线实验，不影响真实报价 | 🟡 低风险：推荐仅供参考，销售保留最终选择权 | 🟡 中低：流程嵌入但保留人工覆盖 |

### Wave 2：远期（+6 个月）

- **技术**：方向 B → 方向 A（贝叶斯分层模型），每笔推荐带置信度
- **业务变化**：
  - 低置信推荐自动推 Team Lead 审批，不再由销售自行判断
  - 高置信推荐逐步放开自动采纳，降低人工审批量
  - 每周自动生成定价报表（采纳率、偏离度、$/HW 趋势）

### Wave 3：远期（+12 个月）

- **技术**：叠加方向 C（价格弹性模型），支持模拟推演
- **业务变化**：
  - 定价策略从「每单被动反应」升级为「提前主动管理」
  - 可回答战略问题：「Q3 HW 预计降 8%，服务 Pen Rate 应该提前调到多少？」
  - 定价决策从依赖个人经验 → 系统策略建议

## 8. 结论

> **做 Dynamic Pricing——让服务的价格跟着硬件的价格走，而不是被硬件价格牵着走。**

6 个月可投产的路径：POC 离线验证 → Pilot 给人用 → Rollout 嵌入流程。不动现有定价体系，在报价环节加一层智能推荐——销售看到的不是「被 AI 替代」，而是「多了个帮算价的助手」。
