III. Two Paths — Trade-offs

Path A — Unified Approach

ISG & IDG use the same Pen Rate method
A1: Both use AI (IDG model)
Pros
  • Single model to maintain, lower long-term cost
  • Consistent methodology, lower communication overhead
  • Future product lines can reuse directly
  • ML team skills fully reusable
Cons
  • ISG lacks sufficient data for meaningful model training
  • ISG cold-start → low confidence → de facto fallback to rules
  • ISG large deal size amplifies model error cost
  • ISG low transaction frequency → stale model updates
A2: Both use lookup table (ISG model)
Pros
  • Fast deployment, no historical data dependency
  • Fully controllable & auditable
  • Approval-friendly
Cons
  • IDG hundreds of SKUs → dimension explosion, unmaintainable
  • Wastes IDG's massive transaction data value
  • IDG cannot respond to HW price fluctuations
  • IDG needs manual rule updates every product season
⚠ Unified risk: optimizing for one side sacrifices the other

Path B — Forked Approach

ISG: fixed lookup  |  IDG: AI computation. Shared engine framework & output format.
Pros
  • Best of both — ISG keeps controllability, IDG keeps scale advantage
  • ISG not forced into AI with insufficient data; IDG not limited by rule tables
  • Shared engine framework reduces forking cost
  • Each product line can iterate independently, no cross-blocking
Cons
  • Two maintenance tracks — team manages both rule tables and ML models
  • Inconsistent methodology across product lines — harder to explain to stakeholders
  • Future unification carries migration cost
  • No cross-learning — ISG patterns cannot feed IDG models
