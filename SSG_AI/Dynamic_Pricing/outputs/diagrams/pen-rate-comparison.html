IDG vs ISG — Dynamic Pricing 方案全维度对比

同一个引擎底座，两种 Pen Rate 来源。不是竞争，是不同业务特征的必然选择。
一、共同点 — 两方案共享同一引擎底座
01
核心公式
ServicePrice = HWPrice × PenRate，服务价格跟着硬件底盘走
02
六步引擎
Intake → Benchmark → Candidate → Score → Guardrail → Output
03
输出格式
Price Band (F/T/S) + Reason Code + Confidence Level
04
四维输入
HW Context / Service Economics / Deal Context / Historical Behavior
05
约束体系
Margin Floor → List Price Ceiling → DOA 三层 Guardrail
06
设计原则
学习而非预设 · 独立于 HW 定价 · 渠道无关引擎
07
落地节奏
渐进信任：POC 离线 → Pilot 参考 → Rollout 嵌入
二、差异对比
维度ISG（服务器）IDG（PC）
PenRate 来源固定查表 — 多维矩阵手工定义AI 计算 — 模型从历史交易中学
模型类型规则引擎（Rule-based）ML 模型（Rule + ML 混合）
HW 特征型号少（数十款）、配置标准化、生命周期长型号多（数百 SKU）、新季更新频繁、配置组合爆炸
交易特征低频大单（$50K–$500K+）高频中小单（$500–$5K）
历史数据量少 — 同型号交易稀疏多 — 可训练 Conversion Probability 模型
Benchmark 构建同服务器型号 × Tier × GEO × 客户段同 HW 价值段（PFV 区间）× Tier × GEO × 客户段
上线速度快 — 2 周定义规则表慢 — 2 月数据清洗 + 训练
可解释性强 — 任何报价可追溯到具体规则格中 — Reason Code + Confidence 补偿黑盒
市场适应性差 — 需人工更新好 — 自动吸收新交易模式
冷启动容易 — 业务专家定义初始值困难 — 借用相似市场先验，Confidence 低
维护成本维度膨胀后不可维护模型需定期重训 + 监控漂移
核心竞争力业务可控、审批友好规模效应、持续优化
三、优劣分析

ISG — 固定查表

规则驱动 · 适合低频高价值
优势
  • 上线极快，不依赖历史数据，PM 拍定 PenRate 即可用
  • 完全可控，业务可直接调整任何格子的取值
  • 审批友好，规则表可审计，合规接受度高
  • 适合低频高价值——单笔 $50K+，错了代价高
劣势
  • 维度爆炸 — Tier × GEO × 型号，格数指数增长
  • 不存在"最优"—只是"业务觉得合理"
  • 无法利用历史成交数据反哺定价
  • HW 涨/降价时 PenRate 不动 — 利润漏出或竞争力不足
  • 新服务器型号上线，PM 凭经验拍 — 和现状一样

IDG — AI 计算

模型驱动 · 适合高频大规模
优势
  • 自动适应 — HW 涨/降价时引擎动态调整 PenRate
  • 捕捉非线性 — 同价位 ThinkPad vs ThinkBook 支付意愿不同
  • 持续学习 — 每笔成交/丢单都在优化模型
  • 规模效应 — 日数百笔交易，AI 优势随数据量增长
  • 可复制 — B2B 引擎训练好后，Consumer/SMB 复用
劣势
  • 冷启动困难 — 新市场无数据时 Confidence 低，退化为规则兜底
  • 需大量训练数据 — 至少几千条历史成交
  • 可解释性弱 — 销售难以理解"为什么推荐 12%"
  • 模型维护成本 — 需监控漂移、定期重训、A/B 验证
  • 上线周期长 — POC 2 月 + Pilot 3 月

结论

不建议用一套方法统一两条线。
ISG 低频高价值 → 数据不足以训练 AI → 规则表 是最优解，投入聚焦规则表维护工具化。
IDG 高频中低价值 → 数据足够 → AI 模型 带来额外收益，投入聚焦模型精度和采纳率。
两条路径共享同一个引擎框架和 Price Band 输出格式，未来可横向整合。
