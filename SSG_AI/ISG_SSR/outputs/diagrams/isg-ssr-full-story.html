1.4 How It Works
What XGBoost Actually Is
An ensemble of decision trees — hundreds of simple yes/no questions, combined
One Decision Tree (example)
ENSEMBLE: ~100–500 TREES
× …
Each tree learns different patterns
1

Each tree asks simple questions

"Warranty ≥ 3yr?" → "Country = NA?" → "Contract ≥ Premier?" Each answer narrows the path.

2

Trees learn from mistakes

Each new tree focuses on the errors of previous ones — "gradient boosting." Sequentially improving.

3

The ensemble votes

All 500 trees contribute a score. Summed and transformed into a probability across all 56 services.

How the Catalog Consumes AI Recommendations

AI model output passes through catalog product logic before reaching the GBB frontend. Not every AI top pick makes it to the bid — and that's by design.

3.1 Catalog Product Logic

From AI Prediction to GBB Display

① AI Model Output

XGBoost multi-class → N plans, Σprob = 1. Each plan: base warranty (Type·Term·SLA) + add-on modules (each with competing options, Σprob = 1 per module).

② Catalog Logic Filter

Existing product rules validate each plan against real-world availability. Plans failing any rule are removed — regardless of AI confidence.

③ Decision Gate

On surviving candidates: any plan prob > 0.75? → Branch 2 (personalized add-on stacking) or Branch 1 (price-tier fallback).

④ GBB Frontend

Exactly 3 warranty cards (Good / Better / Best). Always deterministic — same input = same output.

3.2 GBB Decision Logic

Not Every AI Recommendation Survives the Catalog

The AI model sees statistical patterns — it doesn't know regional availability, contract terms, or product lifecycle. The Catalog layer validates every recommendation against operational reality.

Expected behavior: AI best-pick being filtered by catalog logic is not a bug — it's the system correctly enforcing business guardrails. The AI recommends based on learned patterns; the catalog ensures only valid, deliverable products reach the customer.

The Big Picture
Three Innovations
1
XGBoost for Ranking
Scores structured transaction data with speed, accuracy, and full auditability. Not a black box — every prediction decomposable via SHAP.
2
SHAP for Explainability
Each recommendation traced to specific factors — hardware match, customer profile, geography, deal structure. All auditable.
3
LLM for Translation
Numerical SHAP values become natural-language rationale — per audience, per language. Internal gets data, customers get clarity.
Key Takeaways
Part 1XGBoost is purpose-built for structured ranking — faster, cheaper, and more auditable than an LLM for this task.
Part 2Price-aware optimization + SHAP explainability + LLM translation form a complete loop: rank, explain, communicate.
Part 3Catalog integration turns model output into production-ready GBB cards — with filtering, safety gates, and role-specific explanations.
