Part 3: Where Tuning Decisions Are Required

The following four scenarios require explicit business decisions about how aggressive or conservative the model should be. Each scenario presents the current behavior, the tuning options, and the trade-offs. These are not model bugs — they are policy choices about how the recommender should behave.

1. Overall Model Posture: Conservative → Should We Push More Aggressively?

TUNING REQUIRED
Current behavior: The model is net-conservative. When it's wrong, it recommends a lower-value product 36.2% of the time vs. a higher-value one 28.2% of the time. The remaining 35.6% are value-neutral (same type, wrong term or SLA).

(model recommends more expensive/longer)
96 (28.2%)

Option A: Keep Conservative

Do nothing. Accept the current 36:28 conservative tilt. Pros: lower risk of seller rejecting AI as "too pushy." Cons: may leave revenue on the table in cases where a longer/higher-tier recommendation would have been accepted.

Option B: Shift to Balanced ← Recommended

Tune the model toward balanced aggressive/conservative ratio (~1:1). Apply a small bias toward longer terms and higher warranty tiers where the model is uncertain. Pros: captures incremental revenue with minimal seller friction — the seller can always downgrade. Cons: requires A/B testing to find the right threshold.

2. Warranty Term: 60M → 36M Downgrade (Largest Error Source)

TUNING REQUIRED
Current behavior: 76 contracts where the customer bought 60-month coverage but the model recommended 36-month. This is the single largest harmful error pattern — the customer wants 5-year coverage, the model offers 3-year. The reverse (36M→60M) is only 60 contracts — a net downgrade bias of +16 contracts.

Option A: Keep as-is

Accept the current term confusion. Pros: no model changes. Cons: 76 customers per ~2,300 receive a shorter-term recommendation — quantifiable revenue leakage.

Option B: Bias Toward Longer Term ← Recommended

When the model is uncertain between two term options, default to the longer one. The seller can always downgrade. This directly addresses the #1 error pattern (46.8% of all misses). Expected impact: reduce 60M→36M errors without increasing 36M→60M errors (already acceptable).

3. PSP Server: Should the Model Push Premium Tier More?

TUNING REQUIRED
Current behavior: When the customer actually bought PSP Server (premium tier), the model recommended Premier (standard tier) in 31 of 162 cases. PSP Server Top-1 is only 68.5% — the model is timid about recommending the premium product. This is partly a data imbalance issue (PSP is only 7.1% of training data) and partly a policy question.
PSP Server → Premier (Downgrade)

Premier → PSP Server (Upgrade)
6 / 2,016
Model almost never upsells to PSP

Option A: Fix via Data Only

Just add more PSP Server training samples — don't adjust the model's willingness to recommend it. Pros: cleaner approach, fewer false PSP recommendations. Cons: even with more data, the model will still be conservative on PSP if the features don't strongly signal it.

Option B: Data + Aggressive Bias ← Recommended

Add PSP training samples AND apply a modest bias toward PSP Server. When the model's confidence gap between PSP and Premier is small, default to PSP. The seller can downgrade to Premier with one click. Expected: PSP Server match rate improves from 68.5% toward 80%, with minimal false positives on Premier contracts.

4. SLA Tier: Confusion Is Symmetric — No Directional Tuning Needed

NO TUNING
Current behavior: When the model gets the right warranty type+term but the wrong SLA tier, it's almost perfectly balanced: 51 cases of 24x7→NBD, 57 cases of NBD→24x7. There is no systematic bias in either direction — the model simply can't distinguish these two SLA tiers well enough.

Decision: No directional tuning. This is a feature engineering problem, not a bias problem. The fix is to add stronger SLA-tier signals (hardware criticality, customer industry vertical, subsegment) so the model can differentiate better. No aggressive/conservative tilt needed — the confusion is symmetric. Action: add features in Pilot; monitor if symmetry holds in production.

Net Effect: Three "More Aggressive" Tuning Decisions

The model is currently conservative — it errs on the side of cheaper/shorter recommendations. The three tuning decisions above all push the model to be more aggressive: recommend longer terms, recommend premium tiers more confidently, and balance the overall posture. The seller always retains the ability to downgrade. The net effect should be higher service revenue per hardware unit without degrading the seller experience — because the model is correcting a conservative bias, not adding unwarranted upsell pressure.
