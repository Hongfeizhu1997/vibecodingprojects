## 二、各阶段详解

### 阶段 1: 特征工程与样本构造

**数据来源** (Data Pool, 300+ 字段):

| 维度 | 内容 |
|------|------|
| Hardware | 硬件配置、型号、规格 |
| Service | 服务产品、保修方案、Add-on 模块 |
| Customer | 客户 DMU、Segment、行业 |
| Contract | 合同条款、定价条件 |
| Bid | 报价单属性、国家、Vertical |
| Price | 硬件价值、服务价格 |

**特征处理** (Feature Pool, 50+ 点):

1. **常规特征**: 从 Data Pool 直接提取的结构化特征（客户属性、硬件属性等）
2. **稀疏编码器（Sparse Encoder）**: 对原始特征做映射表征，作为额外特征构造方式。区别于常规特征（直接从 Data Pool 提取），稀疏编码器将高基数类别特征（如 Customer ID、PN、行业代码等）压缩为低维向量表示，补充原始特征中难以捕获的类别共现模式
3. **特征工程流水线**: Feature Embedding → Feature Extracting → Feature Scoring（Engine III 前半段）

**样本构造策略**:

- **问题**: 不同服务产品的标签分布差异大（热门服务高频出现，冷门服务样本稀疏）
- **随机采样**: 对标签差异较大的样本进行 resampling，缓解类别不平衡
- **数据增强**: 对冷门服务产品的训练样本做增强（如基于已有样本的扰动生成），提升模型对长尾产品的泛化能力

---

### 阶段 2: 召回 — 候选集生成

目标：从全量服务产品池中快速筛选出 N 个候选，降低排序阶段的计算压力。

**Engine I — 冷启动引擎（关联规则）**:

- 场景: 新产品 / 新客户 / 无历史配置记录
- 方法: 基于 Association Rule（关联规则挖掘），利用硬件配置 → 服务产品的共现关系
- 逻辑: "买了硬件 X 的客户通常搭配服务 Y"

**Engine II — 推荐引擎（热度 + 关联）**:

- 场景: 有历史数据
- Layer 1 — Popularity Ranking: 同 Segment/Country/Vertical 下最常被选择的服务
- Layer 2 — Product Association: 当前硬件配置最常关联的服务产品
- 输出: 合并去重后的候选服务产品集

**冷热切换机制（✅ 已确认）**:

系统根据输入参数实时判断，无需人工干预：

| 输入情况 | 处理方式 |
|----------|---------|
| 仅个别维度缺失（如缺 Customer 但有 Hardware+Geo） | 自动忽略缺失维度，继续用其他可用因素预测 |
| 核心维度大面积缺失 / 遇到全新元素 | 触发 Engine I 冷启动（关联规则兜底） |

判断维度包括：新客户、新产品、新行业等关键标识。Engine I 和 Engine II 是**硬分流**关系，不存在同时运行的融合模式。

---

### 阶段 3: 排序 — XGBoost 核心模型

> 核心算法: **XGBoost (Extreme Gradient Boosting)**
> 框架: Recall → Ranking 两阶段

**模型输入**:
- 阶段 2 召回的候选服务产品
- 阶段 1 产出的特征向量（常规特征 + 稀疏特征 embedding）

**模型目标**:

- ✅ **多分类（softprob）** — 将用户划分到多个 service 之一，输出概率向量。不是 Learning to Rank。

**模型优化**:

| 优化手段 | 说明 |
|----------|------|
| **贝叶斯超参搜索** | 对 XGBoost 的 n_estimators、max_depth、learning_rate、subsample 等关键参数做 Bayesian Optimization，自动找到最优参数组合 |
| **自定义损失函数** | 总损失 = 交叉熵损失 + β × 非对称价格损失 |

**自定义损失函数详解**:

```
L_total = L_ce(y, ŷ) + β · L_price(y, ŷ)
```

| 组件 | 说明 |
|------|------|
| L_ce | 多分类交叉熵损失（标准分类目标） |
| L_price | 非对称价格损失 — 对高价服务预测错误给予更大惩罚，对低价服务过度推荐也施加约束 |
| β | 价格惩罚系数，**动态自适应衰减**，范围 0.1 - 0.5。训练初期 β 较大（强调价格学习），随训练轮次逐步衰减（让模型回归准确率优化） |

**模型评估（✅ 已确认）**:

| 指标 | 说明 |
|------|------|
| Accuracy | 整体分类准确率 |
| F1-Score | 兼顾精确率和召回率，对长尾类别尤其重要 |

**模型更新周期（✅ 已确认）**:

| 维度 | 节奏 |
|------|------|
| 底层数据 | 每周刷新 |
| 模型全量重训 | 每月一次 |
| 线上推理 | 准实时 |

**安全上线机制**：每次模型更新前自动检测——新模型评估结果必须严格优于旧模型才上线，否则回滚重训。连续多次不达标则暂停本次更新，避免线上劣化。

**模型输出**:
- 每个候选服务产品的预测概率向量，softprob 输出每个类别的概率
- 每个 Add-on 模块内各选项的概率分布

---

### 阶段 4: 业务规则干预

> 对应 PPT "Layer 4: Business Rule Filter"

在模型纯数据驱动的预测分数之上，叠加业务逻辑：

- **基线校准** (Baseline Setting): 对模型输出的分数按业务规则校准（如某些服务产品有最低推荐配额）
- **规则过滤**: 不符合业务策略的推荐直接过滤（如特定国家不可售的服务、已下架产品等）
- **Engine IV**: （LLM 部分无实际作用，忽略；仅保留业务规则过滤 + 基线校准）

---

### 阶段 5: Add-on 推荐（独立下游模块）

> ✅ 已确认：Add-on 不与 Warranty 共用 XGBoost，而是独立下游模块。

**工作流**：

```
XGBoost → Warranty 预测结果
            ↓
关联规则挖掘 → Warranty 与 Add-on 的共现关系
            ↓
计算各 Add-on 在当前 Warranty 下的推荐概率
```

**关键设计**：
- Warranty 和 Add-on 解耦，各自独立建模
- Add-on 依赖关联规则而非 ML 模型，可解释性强
- 输出：给定已选 Warranty 下，每个 Add-on 选项的推荐概率

---

### 阶段 6: GBB 前端展示

AI 输出 N 个保修计划 → 系统检查最高概率是否 > 0.75：

| 条件 | 分支 | 展示策略 |
|------|------|---------|
| max prob ≤ 0.75 | Branch 1 | 按价格排序 → Good/Better/Best 三档，仅展示基础保修 |
| max prob > 0.75 | Branch 2 | 围绕最优计划阶梯叠加 Add-on 模块 |

**LLM 推荐理由**:
- 有统计亮点 → prompt 聚焦具体数据特征
- 无统计亮点 → prompt 使用通用描述模板

## 三、关键设计亮点

1. **召回+排序两阶段**: 降低全量排序的计算开销，召回保证覆盖率，排序保证精度
2. **冷启动兜底**: Engine I 关联规则确保新产品/新客户也有推荐
3. **稀疏编码器**: 对原始特征做映射表征，补充常规特征之外的额外特征维度
4. **价格感知自定义损失**: 多分类交叉熵 + β × 非对称价格损失（β 动态自适应衰减 0.1-0.5），推荐不仅要"准"，还要"价格合理"
5. **业务规则兜底**: 纯 ML 输出 + 业务逻辑双重保障，避免推荐不可售/不合规产品
6. **GBB 阶梯展示**: 给销售灵活选择空间，不是强推单一方案

### 多分类规模（✅ 已确认）

K 值按 Geo 不同，呈现典型长尾分布：

| 区域 | K（候选服务数） |
|------|----------------|
| NA (北美) | 56 |
| LA (拉美) | 31 |
| 其他区域 | 各不同 |

**标签分布**：头部高频服务占绝大多数样本，长尾服务样本稀疏。这也是 Stage 1 数据增强（对冷门服务做样本扰动）的动机。

## 五、算法公式补充（2026-05-29 确认）

### XGBoost 多分类目标

模型将用户 u 分配给 K 个服务类别之一：

```
P(service=k | user=u) = softmax(f_k(u))
                      = exp(f_k(u)) / Σ_j exp(f_j(u))

ŷ_u = [P(k=1|u), P(k=2|u), ..., P(k=K|u)]
```

最终推荐取 Top-N 概率最高的服务。

### 自定义损失函数

```
L_total = -Σ_i Σ_k y_{i,k}·log(ŷ_{i,k})    ← 交叉熵
          + β(t) · L_price(y, ŷ)            ← 价格约束

β(t) = β_0 · γ^t                            ← 动态自适应衰减
       0.1 ≤ β(t) ≤ 0.5
```

其中 β_0 为初始价格惩罚权重，γ 为衰减因子，t 为训练轮次。
L_price 为非对称价格损失——高价服务误判惩罚 > 低价服务误判惩罚。
