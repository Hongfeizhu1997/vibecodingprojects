# Career Opportunity — 求职跳槽定位与机会扫描

> 机会主义跳槽：现状满意度高，只追"特别合适"的机会。厘清方向、薪资预期，建立"跳 or 留"的判断标准。

---

## 项目定位

- **业务线**：个人职业发展 / 求职跳槽
- **核心场景**：方向迷茫 + 薪资预期不清 → 自我定位 → 市场扫描 → 机会评估框架
- **交付模式**：离线分析 + 招聘源爬取 + 可选 cron 机会监控

---

## 核心约束（已确认，2026-08-22）

| 维度 | 结论 |
|------|------|
| 地域 | 成都/天津 = 长期首选；北京 = 仅 2–3 年过渡且岗位特别合适 |
| 企业 | 外企 / 大型国内企业偏海外部门（联想海外类）/ 外企化国企 |
| 方向 | 贴近现状（数字转型、业务流程、AI 落地），往 AI 靠更好 |
| 心态 | 机会主义——现状满意度高（稳定升职、受赏识、有新挑战），只追特别合适的机会 |
| 节奏 | 不急于投递，先定位 + 扫描 |

---

## 项目框架

1. **自我定位**：能力资产盘点 → 市场岗位对标 → 收敛 2–3 个方向
2. **市场扫描**：目标岗位爬取（成都/天津/北京）→ 匹配度 + 薪资区间
3. **机会评估框架**：打分卡（薪资增幅 × 方向契合 × 城市 × 企业 × 发展 vs 现状稳定性）
4. **求职材料**（按需触发，仅当评估判定有值得追的机会）：简历优化 / 求职信 / 作品集
5. **机会监控**（可选）：cron 定时扫新岗位

```
├── PRODUCT_REQUIREMENTS.md    ← 目标、功能需求、验收
├── DECISIONS.md               ← 决策记录（只增不改）
├── SESSION_HANDOFF.md         ← 跨会话交接
├── profile/                   ← 个人画像 + 薪资基线（⚠️ 敏感，gitignore 不入库）
├── positioning/               ← 阶段1 自我定位产出
├── market_scan/               ← 阶段2 市场扫描产出
├── evaluation/                ← 阶段3 机会评估框架
├── outputs/                   ← 最终交付物（报告、机会清单、对标）
├── references/                ← 参考资料（简历原文等，gitignore）
└── archive/                   ← 废弃实验（按需）
```

---

## 敏感信息约定

- 简历原文、精确薪资、手机号/邮箱 → 只存 `profile/` 与 `references/`，`.gitignore` 排除，不入 Git/GitHub
- 所有公开文档（README、报告、机会清单）**不写**精确薪资和联系方式
- 薪资在产出物中只用"税前总包区间"等脱敏口径

---

## 要产出的三个答案

1. 你能去什么方向
2. 你在市场上值多少钱
3. 什么机会才值得离开现状
